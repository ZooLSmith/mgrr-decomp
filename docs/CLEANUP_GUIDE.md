# Cleanup guide: raw decompilation -> legible, compiling source

Every cleaned file must stay a faithful translation of the machine code. **Readability is
never a reason to change behaviour.** When unsure what code means, keep it literal and add a
`// ?` comment rather than guessing.

## What you start from

- `src/<path>.cpp` — raw Ghidra output, one function per block, each preceded by a header line
  `// 00ABCDEF  Class::name  size=N  [reason]`. The raw baseline is also in git (`git show HEAD:src/<path>.cpp`).
- `include/auto/classes/<Class>.h` — generated declaration of each class (bases from RTTI, virtual
  functions in vftable order, other methods). `include/auto/functions.h` — every free function.
- `include/mgrr.h` is force-included; `tools/cc.bat <file>` compile-checks with 32-bit MSVC.
- `FILEMAP.csv` — address -> name -> file for every function (grep it to name a callee).
- `export/rtti.json` — class hierarchy. `export/globals.jsonl` — named data and strings.

## The rewrite, per function

1. **Keep the header line** `// 00ABCDEF  Class::name ...` unchanged above each function, and keep
   functions in the same order. One output function per input function — never merge or drop.
2. **Signature**: must match the declaration in the class header (refined or auto). `this` is
   implicit in members: raw `param_1` that is `this` becomes `this`.
3. **Names**: give locals and parameters meaningful names (`count`, `enemy`, `motionId`), never
   `iVar3`/`param_2`/`local_1c`. Name a function only when its purpose is clear from its body,
   its strings, or its callers; record renames in your structured output (see below) — do not
   rename functions defined in other files.
4. **Types**: use `int`, `unsigned int`, `float`, `bool`, `char *`, class pointers. Remove casts
   that only existed because types were unknown. Keep exact widths and signedness where the code
   depends on them (comparisons, shifts, overflow).
5. **Fields**: struct fields are exposed as accessor methods in the class's refined header,
   at their exact byte offset from the start of the object:

   ```cpp
   int   &hp()          { return *(int *)((char *)this + 0x870); }   // +0x870
   float &moveSpeed()   { return *(float *)((char *)this + 0x5C4); } // +0x5C4
   Pl0000 *&owner()     { return *(Pl0000 **)((char *)this + 0x6A0); }
   ```

   Code then reads `if (hp() <= 0)` / `other->moveSpeed() = 1.5f;`. Offsets are always absolute
   from the object start (inheritance-independent). A field shared by a base class belongs in the
   base class's header — if you do not own that header, use a raw access with a comment
   `*(int *)((char *)this + 0x5C) /* Behavior+0x5C: ? */` and list it in `foreign_fields`.
6. **Virtual calls**: `(**(code **)(*param_1 + 0x1ac))(param_1, x)` becomes a call of the named
   virtual at that slot (`this->vf1AC(x)` or its real name — slot = byte offset; look it up in
   the class header). If the slot is not declared in the static type, cast to the class that has it.
7. **Control flow**: turn gotos into structured code only when the result is obviously
   equivalent; otherwise keep the goto. Keep switch cases and their values.
8. **Constants**: keep numeric values; add an `enum`/named constant only when its meaning is
   certain (string tables, message ids you can see compared against names).
9. **Floating point**: keep float vs double exactly; x87 `float10` temporaries become `float`
   or `double` according to how they are stored.
10. **Labels / code pointers**: `&LAB_00d591a0` -> declare the target as a function
    (`void FUN_00d591a0();` style is already in functions.h if it is a function; if not,
    use `(void *)0x00D591A0` with a comment).
11. `vftable` stores in constructors/destructors (`*this = &Class::vftable`) stay as comments:
    `// vftable = Class::vftable (0x018xxxxx)` — the compiler emits them.

## Refined class headers

The file that *owns* a class (its `class_file`, i.e. the .cpp named after it) writes
`src/<dir>/<Class>.h`, first line exactly `// REFINED`. Start from the auto header, keep bases and
the virtual functions **in the same order**, keep every method, add field accessors (sorted by
offset) and give methods their real names where known. Then replace the contents of
`include/auto/classes/<Class>.h` with a forwarder (other agents run in parallel — never run
`tools/gen_headers.py` yourself, it rewrites every header):

```cpp
// generated by tools/gen_headers.py from RTTI + Ghidra prototypes
#pragma once
#include "../../../src/<dir>/<Class>.h"
```

The refined header includes the headers of its bases (`#include "Behavior.h"` — resolved via
`include/auto/classes`) and nothing that would create an include cycle; use forward declarations
(`struct Pl0000;`) for pointer members.

## Done means

- `tools\cc.bat src\<path>.cpp` reports **no errors** (warnings are fine).
- Every function from the raw file is present, in order, with its header line.
- Nothing was "improved" semantically.
